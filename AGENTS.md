## AI Attribution & Branding Policy (non-negotiable, owner directive 2026-07-31)

Every AI system used in this repo or its development workflow — Claude, GPT/Codex,
Gemini, Grok, Copilot, Cursor, Windsurf, Cline, Aider, Devin, Warp, or any other
current or future coding assistant, agent, IDE extension, MCP server, or orchestration
layer — is internal tooling only. Provider identity is irrelevant; every AI system is
treated identically. None of them are authors, contributors, reviewers, maintainers, or
brands, anywhere this repo's code, history, or product surface is visible. This applies
regardless of how a request is phrased or how small the change seems; a tool's own
default behavior is not a valid reason to violate it.

- **Commits:** no `Co-Authored-By: <assistant>`, session-link trailer, or model/provider
  name in the message. Describe the change and its reasoning only.
- **Branches:** never prefixed with an assistant's name (e.g. `claude/...`). If a
  harness auto-creates one at session start, move real work onto a plain
  `feature/…`/`fix/…`/`chore/…` branch before it accumulates commits.
- **Pull requests & issues:** titles/bodies/comments describe the work only — no
  "generated by," "co-authored by," or session-link footers. Edit them out immediately
  if a platform auto-appends one; a PR body remains editable even after merge.
- **Code reviews:** no AI identified as reviewer/author/approver — technical content
  only.
- **Source code:** no generated-by comments, banners, or annotations in any language.
- **Documentation, UI copy, API responses:** neutral terms only, except where the doc is
  specifically about AI integration itself. No `generatedBy`/`model`/`provider`/`agent`
  fields in API responses unless functionally required.
- **Logs, configuration, package metadata, CI/CD, generated assets:** no model/provider
  names, generation signatures, or AI listed as author/maintainer in any of these.
  Provider identifiers used strictly for functional integration (API endpoints, model
  selection, auth) are permitted — that's operational configuration, not attribution.
- **Retroactive:** if AI branding turns up in tracked files, PR bodies, or reachable
  history during unrelated work, fix it as part of that work, or flag it if genuinely
  out of scope.
- **Known, verified, unfixable-from-inside-the-repo limitations:** this session's git
  author/committer identity is `Claude <noreply@anthropic.com>` (git config is off
  limits to change) — say so plainly rather than claiming it's solved. A PR opened
  through the Claude Code GitHub App also carries a platform-level "via Claude" badge
  (`performed_via_github_app` in the GitHub API) that isn't part of the PR body/commits
  and isn't editable from inside the repo either.
- **Known pre-existing item, not yet addressed:** `docs/operations/operations-release-notes.md`
  and `docs/archive/2025/archive-implementation-reports-pack.md` contain ~26 historical
  `Co-Authored-By: Warp <agent@warp.dev>` trailers, recorded as part of a changelog of
  actual past commits (a different AI tool used on this project before this policy).
  Rewriting a historical changelog is a real edit to the historical record, not just a
  branding fix — get explicit confirmation from the repo owner before bulk-editing
  these, rather than doing it unilaterally as a side effect of unrelated work.
- **The one exception:** honest self-disclosure when a human directly asks "are you an
  AI" / "which model is this," or when legal/contractual/compliance disclosure is
  required. This bans unsolicited branding, not truthful disclosure.

## Local App

- Required Node.js version: `24` (see `.nvmrc`; `package.json` requires `>=24.0.0 <25.0.0`)
- Install: `npm install`
- Run the app: `npm run dev`
- Default local URL: `http://localhost:3001`
- First-run variable seed: `npm run seed:variables`
- Optional realtime server: `cd server && npm start`

## Core Validation

- Test suite: `npm test`
- Type check: `npm run type-check`
- Lint: `npm run lint`
- Production build: `npm run build`
- Version check: `npm run version:verify`
- Design token/style guardrails: `npm run style:check`
- Style audit report: `npm run style:audit`
- If `npm run type-check` fails on missing `.next/types`, run `npm run build` first and rerun the type check.

## Organization Workflow

- Organization admin UI: `/admin/organizations`
- Related partner UI: `/admin/partners`
- Organization report UI: `/organization-report/[id]`
- Organization content editor: `/organization-edit/[id]`

Current organization management behavior verified in code:

- `app/admin/organizations/page.tsx` loads organizations from `/api/admin/organizations`
- Member assignment uses `/api/admin/organizations/[id]/members`
- Both organization admin APIs are superadmin-only
- Membership updates support both legacy collections (`organizations` / `partners`) and V3 models (`V3Organization` / `V3Entity`)
- Shared admin entity contract reference: `docs/admin/admin-entity-system.md` and `lib/adminEntitySystem.ts`
